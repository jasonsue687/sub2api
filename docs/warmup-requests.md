# 预热请求处理

账号创建、编辑和批量编辑中的「拦截预热请求」保留原有开关，并增加 Mock / 转发配置。历史配置未指定处理方式时仍使用 Mock；升级不会自动开启外部转发。

## 生效范围与优先级

预热配置复用账号所属分组，适用于该分组中能使用对应请求模型的请求。网关先按客户端限制、分组、目标平台、混合调度、模型支持和渠道模型限制读取可调度配置；在开启预热的账号中，取 `priority` 数值最小者，同优先级取 ID 最小者。停用、不可调度或不在当前分组的账号不提供配置。调度快照只提供候选账号元数据；读取完整账号配置后再判断预热开关并复核准入，避免把精简缓存中省略的开关误判为关闭。第三方密钥不加入候选元数据。调度快照与账号配置使用现有刷新机制。

这一步只读取配置，不进行账号选择，不读取或写入永久会话绑定，不获取账号并发槽位，也不注册会话容量。多个账号配置不同时，建议统一同组配置，或用账号优先级明确生效者。选定配置不合法或转发失败会直接返回错误，不尝试其他配置或订阅账号。

下文严格识别的桌面 Haiku 标题直连是辅助请求：即使本组开启「仅 Claude Code 客户端」，也允许读取本组预热配置，不转到客户端限制的降级分组。此例外不把请求标记成 Claude Code，不放开普通聊天或其他预热模板的客户端限制；分组、平台、模型权限和其他准入检查继续执行。没有可用的预热配置时仍进入原有普通请求校验。

请求仍须通过鉴权、客户端/模型权限、安全审计、用户并发、余额或订阅额度及在途余额预留检查。未匹配预热、或当前范围没有启用的配置时，保持普通请求流程；严格模式下缺少可靠 session ID 仍返回 `strict_session_id_required`。

## 请求识别与响应

支持 `system` 和消息文本的字符串及文本块数组形式：

- 单条 user 消息 `Warmup`。
- 旧的 `Please write a 5-10 word title for the following conversation:` 模板。
- 旧的 system 新主题/2–3 词标题分析模板。
- 桌面标题直连：Haiku 模型、`max_tokens=200`，system 完整匹配 `You write short session titles. Reply with only the tagged fields the prompt asks for.`（忽略空白格式差异），且只有一条非空纯文本 user 消息、没有工具声明或工具选择。system 和 content 支持字符串或显式 text 块数组；不依赖 user 正文的开头措辞。该新增规则不覆盖 Opus 或 CLI 回退的请求结构。
- 单条 user 消息以生成标题指令开头，要求 2–5 个词，包含 `<description>…</description>` 和 `<title>…</title>` 输出约定，并与标题/助手 system 提示相符。正文引用或解释模板不会因包含 `title` 一词而被拦截。

Mock 为 XML 模板返回 `<title>New Conversation</title>`，为旧主题分析模板返回 JSON，其余预热返回 `New Conversation`；Mock 不记录付费 token。SuggestionMode 和 Haiku 连通性探测保持各自的原有拦截路径，分别返回空文本和 `#`，不会调用标题转发模型。

桌面标题直连在 Mock 模式返回 `<title>New Conversation</title>`，不生成分支名。转发模式保留第三方返回的标签文本，包括可选的 `<branch>` 字段，不将整个结果再次包成一个 `<title>`；第三方须遵循请求中的标签输出约定。

转发只发送必要的 system、文本消息、输出上限和配置的模型，不携带入站认证、metadata、会话头或订阅账号凭据。支持 OpenAI Chat Completions 和 Anthropic Messages 兼容接口。输出最多 1024 tokens，上游响应最多 1 MiB。

外部请求使用非流式上游接口，完整结果到达后适配为客户端请求的 Anthropic JSON 或完整 SSE 事件序列。因此流式客户端兼容，但标题生成期间不会逐 token 推送。取消和 1–120 秒超时会中止外部请求。HTTP 错误、无效响应或缺失用量返回明确错误，禁止自动回落为 Mock 或调用订阅账号。

## 配置示例

在账号编辑页面开启预热，选择「转发到其他平台」：

| 字段 | DeepSeek 示例 |
| --- | --- |
| 接口协议 | OpenAI Chat Completions |
| Base URL | `https://api.deepseek.com/v1` |
| API Key | 该平台的密钥 |
| 上游模型 | `deepseek-chat` |
| 超时时间 | 30 秒 |

Base URL 使用 API 根地址，可带 `/v1`；不带时补充 `/v1`，再按协议追加 `/chat/completions` 或 `/messages`。执行时遵守现有上游 URL 安全策略，不跟随重定向。API Key 使用已有凭据存储与脱敏机制，前端只显示是否已配置；编辑时留空保留原值，输入新值替换。密钥不出现在响应和审计日志中。

## 用量与计费

成功转发通过现有必达用量任务记录实际输入、输出、缓存 token，包括 DeepSeek 缓存命中和 Anthropic 缓存创建时长。记录关联配置所属账号用于追踪，以 `/v1/messages/warmup` 标识预热，保留客户端请求模型，同时按配置的实际外部模型查价。部署前应配置外部模型价格；未定价模型沿用系统原有计价行为。

用户余额、订阅及 API Key 配额沿用现有计费机制。外部转发不更新配置账号的上游配额、最后使用时间或缓存覆盖策略，不创建绑定或占用会话容量。断开前已经收到完整上游结果的请求仍提交用量；在获得上游用量之前取消或失败的请求无法推算外部平台实际收费。

关闭开关即可恢复普通处理；切回 Mock 即可停止付费转发。无需数据库迁移。本改动不包含生产部署。
